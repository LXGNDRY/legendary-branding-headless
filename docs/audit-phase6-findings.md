# Audit Phase 6 — Accessibility & Performance: Findings

Ref: `docs/full-site-audit-plan.md` Phase 6. Status legend: **Pass** / **Gap** / **Fixed**.

| # | Item | Status | Detail |
|---|---|---|---|
| 26 | Automated a11y audit (axe/Lighthouse) across golden-journey routes | **Fixed** | No automated accessibility testing existed anywhere in the repo prior to this — confirmed via dependency grep (`axe`/`lighthouse` absent from `package.json`) and a search of `e2e/` (a false-positive substring match on "taxes" was the only hit). Added `@axe-core/playwright` as a devDependency and a new `e2e/a11y.spec.ts` auditing the 6 golden-journey routes most representative of real traffic (homepage, collections index, all-products collection, journal index, cart, search) against WCAG 2.0/2.1 A+AA rule tags. The test fails the build on any `serious`/`critical`-impact violation, matching CLAUDE.md's WCAG AA bar, while surfacing `moderate`/`minor` findings non-blockingly (axe's own docs note some of those rules are opinionated best-practices beyond strict AA). Runs automatically in CI as part of the existing E2E matrix (same `*.spec.ts` glob, same browser projects) — this phase could not execute it end-to-end in this sandbox (no live Storefront credentials, the same documented limitation hit in earlier phases), so its first real run will be in CI on this PR. |
| 27 | Raw `<img>` sweep (should be zero) | Pass | Re-confirmed, repo-wide: zero raw `<img>` tags remain except the one deliberate, already-reviewed exception in `HeroSplit.tsx` (Phase 5's findings — responsive art-direction `<picture>` that Hydrogen's `<Image>` can't express). Every fix from Phase 5 holds. |
| 27 | CDN domain + explicit width/height on images (CLS prevention) | Pass | Sampled across the fixes made in Phases 4-5 (`account.orders.tsx`, `Lookbook.tsx`, `RecentlyViewed.tsx`, `SearchTypeahead.tsx`, `ContentBlocks.tsx`) plus pre-existing `<Image>` usages (`ProductCard`, `ProductGallery`, hero/section components) — all resolve through Shopify's `cdn.shopify.com` and all pass explicit `width`/`height`. |
| 28 | Bundle-size baseline / regression check | **Fixed (baseline recorded)** | No recorded baseline existed to check against. Recorded one from this phase's `npm run build` output (client bundle, gzip-uncompressed byte sizes from Vite's manifest): largest chunks are `index-*.js` (~494 KB, the shared vendor/React chunk), `entry.client-*.js` (~141 KB), and a secondary vendor chunk (~132 KB); every route-level chunk is well under 40 KB, with most resource routes (`api.*`, `[robots.txt]`, `[sitemap.xml]`, `[site.webmanifest]`) correctly tree-shaken to a 1-byte stub (no client JS needed for a pure-loader resource route). No new large client-side dependency was added this audit — the only new dependency (`@axe-core/playwright`) is a devDependency used solely in `e2e/`, never bundled into the shipped app. Future phases/PRs should diff `npm run build`'s Vite output against these figures and flag any route-level chunk that newly exceeds ~50 KB or any new top-level vendor chunk. |

## Summary
1 real, fixed gap: zero automated accessibility testing existed, despite CLAUDE.md's explicit WCAG AA requirement — added a real axe-core-based E2E suite covering the 6 highest-traffic routes, wired into the existing CI E2E matrix. The raw-`<img>`/CLS sweep re-confirmed Phase 5's fixes hold with no regressions. Bundle size has no prior regression to compare against but now has a recorded baseline for future phases to check against, and no unjustified new client-side dependency was found. Full local gate (`build && typecheck && lint && test`) green; the new a11y suite itself requires live Storefront credentials to execute and will get its first real run in CI.

Next: Phase 7 — end-to-end verification (full Playwright suite + live preview/production smoke tests).
