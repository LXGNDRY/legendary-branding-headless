# Full-Site Code Audit Plan — Enterprise/Fortune-500 Readiness

Scope: every section of `legendary-branding-headless`, checked against what a Fortune-500-grade
production storefront is expected to have: correctness, resilience, security, performance,
accessibility, SEO, i18n, and clean architecture. Ordered easiest/fastest-to-verify first, in
"verified slices" — each slice ends with `npm run build && npm run typecheck && npm run lint
&& npm run test` (build before typecheck, matching CI and CLAUDE.md — `.react-router/types` is
generated by the build and isn't tracked, so a fresh checkout has no types to check without it
first), plus a scoped manual/E2E check, before moving to the next.

Current inventory (ground truth, read from the repo):
- 30 route files in `app/routes/` (storefront pages + 6 `api.*` endpoints + 3 bracket resource routes)
- `app/components/`: `layout/` (5), `sections/` (18), `ui/` (19), `seo/` (3), `chat/` (1) — 46 files total
- `app/lib/`: 21 files (14 implementation + 7 co-located `.test.ts`: cache, cart, context, i18n, market, security, session)
- 8 locale catalogs in `app/locales/`
- CI: `.github/workflows/oxygen-deployment-1000180490.yml` — quality gate (codegen/typecheck/lint/test/build) + E2E matrix (chromium/webkit/mobile/mobile-safari) + Branch Topology + Deploy
- `e2e/commerce.spec.ts`, `e2e/golden-journeys.spec.ts` (Playwright)
- `scripts/`: PR-governance validator, release-env validator, storefront-token validator (each with its own test)

---

## Phase 1 — Static/config correctness (fastest, no server needed)

1. **TypeScript config & build health**
   - Confirm `tsconfig.json` `rootDirs` still includes `./.react-router/types` (CLAUDE.md hard requirement).
   - Run `rm -rf .react-router && npm run build && npm run typecheck` clean, zero errors, zero `@ts-ignore`.
2. **Lint & dead code**
   - `npm run lint` clean.
   - `grep -rn "console.log\|debugger\|TODO" app/` — must be empty per CLAUDE.md (one-line `// NOTE:` exempted).
   - `grep -rn "eslint-disable\|@ts-ignore" app/` — must be empty.
3. **Dependency hygiene**
   - `npm audit` — no high/critical.
   - Confirm no `"latest"` version ranges in `package.json`.
   - Confirm `package-lock.json` is in sync (`npm ci` succeeds, not just `npm install`).
4. **Env/config contract**
   - Diff `.env.example` keys against `env.d.ts` `Env` interface — every key present both places, placeholders only (no real secrets) in `.env.example`.
   - Confirm `app/lib/context.ts` fails fast (throws, not silent default) on each required var.
5. **CI workflow shape**
   - Re-verify the 10-step pipeline order against CLAUDE.md (build before typecheck, no `secrets` in step-level `if:`, `--legacy-peer-deps` on both jobs).
   - Confirm `scripts/validate-pr-governance.mjs`, `validate-release-env.mjs`, `validate-storefront-token.mjs` each still have a passing co-located test and are actually wired into a workflow step (not orphaned scripts).

## Phase 2 — Library layer (`app/lib/`, unit-testable, no browser)

Go file-by-file; for each, confirm an existing test covers the real behavior (not just a smoke test), and read the implementation for correctness:

6. **`session.ts`** — `AppSession`: httpOnly/sameSite/secret rotation actually enforced; test covers rotation + tampering rejection.
7. **`cart.ts`** — discount/subtotal math (the exact class of bug fixed in PR #220); test covers multi-line, multi-discount, currency-mismatch cases.
8. **`market.ts`** — country/currency/locale resolution; test covers fallback when Shopify Markets data is incomplete.
9. **`i18n.tsx`** — `translate()`/`useTranslation()`; confirm every `TranslationKey` used in components exists in **all 8** locale JSONs (not just `en`), via a script diff, not spot-check.
10. **`context.ts`** — env validation; test covers each missing-var failure path individually.
11. **`security.ts`** — CSP/headers; test asserts the actual header value, not just "a CSP exists" — cross-check against what's live (curl production headers and diff).
12. **`rate-limit.ts`**, **`customer.ts`**, **`judgeme.ts`**, **`nav.ts`**, **`cache.ts`**, **`sentry.server.ts`**, **`monitoring.ts`**, **`fragments.ts`** — no existing test file for several of these; flag each untested file explicitly as a gap rather than assuming correctness, and add minimal unit coverage for the ones with real branching logic (judgeme badge parsing, nav menu resolution, cache TTL tiers).

## Phase 3 — SEO/schema layer (already partially audited — close remaining gaps)

13. Re-check `SeoSchema.tsx` functions not touched in the recent PRs (`organizationSchema`, `websiteSchema`, `breadcrumbSchema`, `faqPageSchema`, `collectionPageSchema`, `articleSchema`) for the same www-canonical/real-data discipline already applied to `productSchema`.
14. Confirm `breadcrumbSchema`/`articleSchema` are actually called from every route that should emit them (`collections.$handle`, `products.$handle`, `journal.$articleHandle`, `policies.$handle`) — grep call sites vs. route list, flag any route missing structured data it should have.
15. hreflang: confirm this remains a documented, un-actioned architectural gap (single-URL client-side i18n) rather than silently dropped — no code change expected here without an explicit decision.

## Phase 4 — Route-by-route functional audit (the bulk of the work)

For each of the 30 routes, verify: loader error/empty/loading states are explicit, meta/canonical present, no hardcoded product/price/copy, and matching E2E coverage exists.

16. **Storefront pages**: `_index`, `collections._index`, `collections.$handle`, `products.$handle`, `search`, `journal._index`, `journal.$articleHandle`, `pages.$handle`, `policies.$handle`, `cart`, `wishlist`.
17. **Account pages**: `account.tsx` (layout), `account._index`, `account.login`, `account.register`, `account.authorize`, `account.logout`, `account.addresses`, `account.edit`, `account.orders` — confirm auth-gating is consistent (logged-out user hitting any of these redirects correctly, no flash-of-protected-content).
18. **API routes**: `api.chat`, `api.market`, `api.newsletter`, `api.search`, `api.waitlist`, `api.wishlist` — confirm each validates input, rate-limits where user-supplied (newsletter/waitlist/chat), and returns sanitized errors (no stack traces per CLAUDE.md security rule).
19. **Resource routes**: `[robots.txt]`, `[sitemap.xml]`, `[site.webmanifest]` — re-confirm live behavior post-merge (already fixed, this is a regression check).
20. **Catch-all**: `$.tsx` — confirm true 404 status code (not soft-404) across a sample of nonsense paths.

## Phase 5 — Component layer wiring

21. **`layout/`** (Header, Footer, AnnouncementBar, CartDrawer, MobileMenu): confirm each is driven by root-loader data (menus, cart, announcement), not hardcoded; confirm CartDrawer math matches `cart.ts` (no divergent duplicate logic).
22. **`sections/`** (18 homepage/PDP/PLP sections): for each, confirm the data it renders traces back to a Storefront API query or Judge.me fetch — zero hardcoded product/price/copy per CLAUDE.md's "never hardcode" rule. Special attention to `DropTimer`, `FitCheck`, `BeforeAfter`, `Lookbook` — newer/more bespoke sections most likely to have crept-in placeholder data.
23. **`ui/`** (19 primitives): confirm `<Placeholder>` usage count — every instance should map to a tracked Milestone-12 gap, not a forgotten one; confirm `ProductGallery`/`ProductCard` variant-image sync (the exact bug class fixed in PR #223) has test/E2E coverage so it can't silently regress.
24. **`seo/Analytics.tsx`**: confirm Shopify `Analytics.Provider` wiring still matches Milestone 10 compliance (cookie consent gates it correctly).
25. **`chat/ChatWidget.tsx`**: confirm it degrades gracefully when `api.chat` backend/key is unavailable (no unhandled promise rejection surfaced to the user).

## Phase 6 — Accessibility & performance

26. Run an automated audit (axe or Lighthouse via Playwright) across the golden-journey routes; cross-check against CLAUDE.md's WCAG AA requirement — every interactive element has `aria-label`/visible label, contrast AA.
27. Image audit: grep for any raw `<img>` tag (should be zero — Hydrogen `<Image>` only); confirm CDN domain + explicit width/height on a sample of product/collection images to prevent CLS.
28. Bundle-size check: `npm run build` output sizes, flag any client bundle regression vs. a recorded baseline; confirm no new large client dependency was added without justification (cross-check `package.json` diff history).

## Phase 7 — End-to-end verification

29. Run the full Playwright suite (`commerce.spec.ts`, `golden-journeys.spec.ts`) locally against a disposable `.env` with placeholder-but-structurally-valid credentials where possible, or document precisely which journeys can only be verified in CI/preview (same limitation hit during the webmanifest test — be explicit, don't overclaim).
30. Smoke-test the live Oxygen preview/production URL for each phase's fixes post-deploy (same method used for the canonical-domain and webmanifest fixes): curl key routes, confirm status codes, headers, and spot-check rendered HTML for the specific fields just audited (JSON-LD, canonical, meta).

## Phase 8 — Reporting

31. Produce a single findings doc: for every item above, record **Pass / Gap / Fixed-in-this-pass**, with file:line references — the same standard used in the prior SEO audit — so this becomes a repeatable checklist for future passes, not a one-off narrative.

### Execution notes
- Work one phase at a time, each phase = one `claude/*` branch → PR → `dev`, per CLAUDE.md branch strategy — do not batch unrelated phases into one PR.
- Any real bug found (not just a style nit) gets fixed in the same slice it was found in, verified, then committed — matching the "verified slices" method already used for the SEO-audit PRs (#253/#254).
- Anything touching checkout, payments, DNS/Markets, or Shopify Admin data is out of scope per CLAUDE.md hard constraints, even if discovered as a "gap" — report only, never modify.
- Per standing instruction, resulting `dev → main` release PRs auto-merge once CI is fully green and `mergeable_state` is `clean` — no per-release confirmation needed unless something unusual (e.g. a real Codex/reviewer finding) surfaces first.
