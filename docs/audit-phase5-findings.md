# Audit Phase 5 — Component Layer Wiring: Findings

Ref: `docs/full-site-audit-plan.md` Phase 5. All 46 files under `app/components/` were read in full (layout/5, sections/18, ui/19, seo/3, chat/1), delegated to a sub-agent with instructions to report only high-confidence findings and cross-check against Phases 1-4 first. 7 real findings came back; all verified and fixed here, except one deliberate, reviewed exception.

| # | File | Status | Detail |
|---|---|---|---|
| 1 | `app/components/layout/MobileMenu.tsx` | **Fixed (removed)** | Fully dead code — `grep` for importers across the app returns zero hits. `Header.tsx` defines and uses its own separate inline `MobileMenu` function (same name, different component, already has the `useFocusTrap` hook the historical docs describe). The orphaned file also still contained fabricated placeholder social links (`href="#"` for Instagram/TikTok/YouTube) — the exact anti-pattern already found and removed from `Footer.tsx` in an earlier pass. Deleted as dead code per CLAUDE.md; nothing referenced it. |
| 2 | `app/components/ui/TrustStrip.tsx` | **Fixed (removed)** | Also fully orphaned (zero importers anywhere in the repo). Its hardcoded `ITEMS` array included `"Free Shipping" / "On orders over $100"` — a live landmine: if ever wired back in, the same stale-pricing bug class fixed in Phase 4 would reappear verbatim. Deleted. |
| 3 | `app/components/sections/StatStrip.tsx` + `app/routes/_index.tsx` | **Fixed** | `StatStrip`'s `DEFAULT_STATS` hardcoded `"$100+" / "Free Shipping"` as an independent literal, and the homepage calls `<StatStrip />` with no `stats` prop, so this hardcoded figure renders live on `/` today. The same `$100` figure was already duplicated a third time in the homepage's `MARQUEE_ITEMS` ("FREE SHIPPING OVER $100"), and a fourth time as `CartDrawer.tsx`'s local `FREE_SHIPPING_THRESHOLD` constant — four independent copies of one business rule that isn't Storefront-API-queryable (it's a merchant shipping-settings rule, not product data). Extracted a single `FREE_SHIPPING_THRESHOLD` export from `app/lib/cart.ts` and pointed `CartDrawer.tsx`, `StatStrip.tsx`'s default, and the homepage marquee string at it, so the figure can now only drift in one place if the real threshold ever changes. |
| 4 | `app/components/sections/Lookbook.tsx` | **Fixed** | Raw `<img>` for the product hover-popup thumbnail — the explicit CLAUDE.md hard constraint ("never use `<img>` directly"). Every other image in this same file already correctly used `<Image>`. Switched to `<Image data={item.product.image} ... width={64} height={80} />`. |
| 5 | `app/components/ui/RecentlyViewed.tsx` | **Fixed** | Raw `<img>` for product thumbnails (image stored as a plain URL string in a cookie, not a full Storefront `Image` object). Switched to `<Image data={{url: p.image}} ... width={400} height={533} />`. |
| 6 | `app/components/ui/SearchTypeahead.tsx` | **Fixed** | Raw `<img>` for predictive-search result thumbnails, despite `Image` already being imported in this file for other uses. Switched to `<Image data={product.featuredImage} ... width={48} height={56} />`. |
| 7 | `app/components/sections/ContentBlocks.tsx` | **Fixed** | Raw `<img>` for `image_text` metafield blocks (image is a plain URL string from unstructured page-metafield JSON, not a full Storefront `Image` object — this is why it wasn't already using `<Image>`). Switched to `<Image data={{url: block.image}} ... width={800} height={600} />`. |
| — | `app/components/sections/HeroSplit.tsx` | Reviewed, not changed | Uses a raw `<picture>`/`<source>`/`<img>` for the homepage hero, with two campaign-photo CDN URLs hardcoded as module constants. This is a **deliberate, documented exception**: the hero needs true responsive art-direction (different source images per breakpoint via `srcSet`), which Hydrogen's `<Image>` component doesn't support — it resizes one image, it doesn't switch between two different ones at a breakpoint. The existing code already achieves CDN-side resizing via Shopify's `&width=` query params (the same optimization `<Image>` would provide) and has explicit `loading`/`fetchPriority`/`decoding` hints. Since these are campaign photos with no Storefront API equivalent (confirmed by the in-code comment this mirrors the live theme's own hero section), forcing a migration to `<Image>` would either break the responsive art-direction or require inventing a data source that doesn't exist. Left as-is; flagged here for visibility rather than silently passed. |

Confirmed clean, no action needed: `<Placeholder>` usage (5 sites, all legitimate "real imagery not yet available" cases per the tracked Milestone-12 gap); `ProductGallery.tsx`/`ProductCard.tsx`'s variant-image-sync safeguards (PR #223 bug class) remain intact; `seo/Analytics.tsx`'s script loaders are correctly gated behind cookie consent (Milestone 10); `chat/ChatWidget.tsx` degrades gracefully on a fetch failure or non-OK response (try/catch, user-facing error message, no unhandled rejection); `DropTimer.tsx`/`FitCheck.tsx`/`BeforeAfter.tsx` (the sections flagged as highest-risk in the original plan) are all fully props-driven with zero hardcoded data.

## Summary
7 real findings, 6 fixed and 1 reviewed-and-accepted as a deliberate exception: 2 dead components removed (one carrying fabricated social links, one carrying a dormant hardcoded-price bug), 1 live hardcoded-price bug fixed by consolidating 4 independent copies of the same business constant into a single source of truth, and 4 raw-`<img>` hard-constraint violations converted to Hydrogen's `<Image>`. Full gate (`build && typecheck && lint && test`) green throughout, 123/123 tests passing (no new tests needed — these were component-level JSX/data-flow fixes with existing coverage via the golden-journey E2E suite).
