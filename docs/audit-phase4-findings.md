# Audit Phase 4 — Route-by-Route Functional Audit: Findings

Ref: `docs/full-site-audit-plan.md` Phase 4. All 30 routes in `app/routes/` were read in full. Status legend: **Pass** / **Gap** / **Fixed**.

Delegated the initial read-through to a sub-agent with instructions to report only high-confidence, reproducible findings (not style nits or speculative issues) across: loader error/empty/loading states, hardcoded data, account-route auth-gating consistency, API-route input validation/rate-limiting/error sanitization, resource-route correctness, and sibling-route consistency. 5 real findings came back; all verified and fixed here.

| # | File | Status | Detail |
|---|---|---|---|
| 1 | `app/routes/search.tsx` | **Fixed** | `meta` returned `{robots: 'noindex, follow'}` — not a recognized React Router meta-descriptor shape (only `{name, content}`/`property`/`httpEquiv`/`tagName` render a `<meta>` tag). This silently meant `/search` result pages were **never actually noindexed**, despite the Phase 3 report assuming they were. Fixed to `{name: 'robots', content: 'noindex, follow'}`, matching the correct pattern already used in `$.tsx` and `account.tsx`. |
| 2 | `app/routes/api.market.ts` | **Fixed** | The only one of the 6 `api.*` routes with no rate limiting, despite doing a live Storefront API query plus a cart `updateBuyerIdentity` mutation per request. Had `requireSameOrigin` (CSRF) but no throttle. Added `rateLimitMiddleware(request, 'market', 10)`, matching the pattern in `api.waitlist.ts`/`api.newsletter.ts`/etc. |
| 3 | `app/routes/policies.$handle.tsx` | **Fixed** | Any unrecognized `handle` (not a real Shopify page/policy, not in `PAGE_TITLES`) fell through to `bodyHtml: null` and rendered a 200 OK "Content for this page is not available" placeholder — a soft 404, indexable by search engines and inconsistent with the sibling `pages.$handle.tsx`, which correctly throws a 404 `Response` for the same class of dynamic-handle lookup. Fixed by throwing a 404 when `!bodyHtml && !(handle in PAGE_TITLES)` — careful to keep the `contact` handle (and other `PAGE_TITLES` entries that intentionally have no body, like the contact form block) working exactly as before. |
| 4 | `app/routes/products.$handle.tsx` | **Fixed** | The PDP's "Shipping & Returns" accordion hardcoded shipping copy and dollar thresholds directly in JSX ("$5 on orders under $100... free on $100+... $12 express...") — a direct violation of CLAUDE.md's "never hardcode prices... or copy" rule, and the exact kind of staleness risk already flagged once before for this storefront (the free-shipping-threshold fix in an earlier PR). Since shipping rates aren't exposed as structured Storefront API data (only as the policy's unstructured HTML body, already rendered correctly on `/policies/shipping-policy`), the safe fix was to remove the specific hardcoded figures from the PDP copy and link out to the real policy page as the single source of truth, rather than inventing a duplicate data path. |
| 5 | `app/routes/account.orders.tsx` | **Fixed** | Order line-item thumbnails used a raw `<img src={item.image.url} .../>` — the only raw `<img>` found across all 30 routes, and an explicit CLAUDE.md hard constraint ("never use `<img>` directly, always use Hydrogen's `<Image>`"), also skipping the required explicit `width`/`height` for CLS prevention. The query already fetches `width`/`height` on this field (already typed in the loader's `image` type), so switched to `<Image data={item.image} ... width={64} height={64} />` with no query changes needed. |

Confirmed clean, no action needed: all 8 `account.*` routes apply an identical `if (!customerAccount) throw 503` → `isLoggedIn()` → `redirect('/account/login')` auth-gating pattern; the other 5 `api.*` routes (chat/newsletter/waitlist/wishlist/search) all validate/sanitize input, rate-limit, and return clean non-leaking error messages; all 3 resource routes (`[robots.txt]`, `[sitemap.xml]`, `[site.webmanifest]`) remain correct from earlier work; the `$.tsx` catch-all correctly throws a true 404 (not a soft one).

## Summary
5 real, fixed findings across routes: one SEO-breaking meta-shape bug, one missing-rate-limit inconsistency, one soft-404 inconsistency (same bug class the plan explicitly asked to check for, just on a different route than the catch-all), one hardcoded-pricing/copy violation, and one raw-`<img>` hard-constraint violation. Full gate (`build && typecheck && lint && test`) green throughout, no new tests added this phase (these are route-level JSX/behavior fixes without existing route-test infrastructure beyond E2E, which already exercises the golden journeys touched here).
